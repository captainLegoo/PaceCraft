> **跨生态跑者 AI 数据与训练中心 · 隐私至上的个人耐力运动操作系统**

**PaceCraft** 专为追求科学训练与隐私安全的严肃跑者打造。它打破单一运动手表品牌的生态围墙（**首发生态现已深度支持高驰 COROS 与佳明 Garmin 中国区 / 国际区**，支持双表同时绑定），在完全由你掌控的本地环境中完成数据聚合、分圈清洗、同场双表微观比对、自建真实跑力预测、马拉松备赛体检与 AI 智能教练分析。

**所有数据 100% 仅持久化保存在你个人的电脑本地，不经由任何第三方云端。**

---

## ✨ 核心特性

- 🏃 **跨生态运动手表多源接入与同场比对**
  - **COROS 高驰**：基于官方开放平台与 MCP 协议，支持一键 Web OAuth 授权与自动增量同步。
  - **Garmin 佳明**：已接入佳明官方 Personal API（深度支持**中国区与国际区**），支持活动时序与 `.FIT` 原始文件解析。
  - **同场双表重叠去重与比对 (Head-to-Head Compare)**：同场佩戴高驰与佳明训练时，系统自动识别时间重叠并去重，杜绝跑量与负荷翻倍；支持同场次深度微观比对，横向评估不同手表的 GPS 轨迹、光电/心率带公差、配速漂移与步频稳定性。
  - **多品牌生理健康与 HRV 接入**：同步佳明夜间睡眠分期（深睡、浅睡、REM）、睡眠评分、夜间 HRV 平均值与平衡状态，以及高驰日常生理指标，支持动态生态视窗切换。
  - **统一 Banister EWMA 训练负荷与 ACWR**：归一化 Edwards TRIMP 聚合全品牌有效训练，连续推算短期疲劳（ATL）、长期体能（CTL）与急慢性负荷比（ACWR 0.8–1.3 甜点区）。
- 👥 **多跑友档案物理隔离 (Multi-Profile)**
  - 一台电脑支持多个跑友/家庭成员自由切换。
  - 每个档案拥有专属的 SQLite 数据库、Token 与海拔缓存，数据毫秒级热切换且 100% 物理隔离。
- 📈 **自建真实能力预测 (不依赖官方评分)**
  - 脱离单一厂商闭源黑盒评分，基于真实比赛锚点与连续分圈滑动窗口，拟合个人 Riegel 疲劳衰减指数与无氧阈值配速。
  - 多模型加权合成，给出 5K / 10K / 半马 / 全马的置信区间与海平面等效成绩。
- 🏁 **赛事画像与马拉松备赛体检**
  - 上传 GPX 轨迹反查 30m 高精度 DEM 海拔剖面，计算爬坡率与下坡代偿。
  - 动态滚动训练窗口监控：近 4 周周均、训练负荷比（ACWR）、有氧占比、长距离拉练完成度。
- 🤖 **AI 深度复盘与智能教练 (BYOK)**
  - 支持接入主流大语言模型（Claude、DeepSeek、OpenAI、Qwen/通义千问、智谱 GLM、硅基流动、Ollama 本地模型等）。
  - **AI 场次分析**：自动识别间歇组结构（如 `1km×10`）与爬升代价，避免机械化误判掉速。
  - **AI 备赛决策 & 课表建议**：根据当前疲劳状态与比赛剩余天数，提供周期化减量与重点突破建议。
- 🖥️ **全平台桌面客户端 & 现代化交互**
  - 基于 Tauri 2.0 构建轻量桌面原生应用（20~30MB），支持 macOS（`.dmg`）与 Windows（`.exe`）。
  - 深度优化的暗黑 / 明亮（浅色）自适应主题，零外部图表库依赖的极速手绘 SVG。

## 🚀 快速使用

### 方式一：直接下载桌面安装包（推荐，开箱即用）

无需配置 Node.js、Bun 或终端环境：

1. 前往 [Releases 发行页](https://github.com/captainLegoo/PaceCraft/releases) 下载对应系统的最新安装包：
   - **macOS**：下载 `.dmg` 文件，打开后拖入 Applications 目录。
   - **Windows**：下载 `.exe` 安装程序直接运行。
2. 打开 PaceCraft，根据界面引导点击 **「连接运动手表」** 完成高驰 COROS 网页授权或佳明 Garmin（中国区 / 国际区）Personal API 绑定（支持同时连接多块手表）。
3. 点击 **「立即同步」**，系统将自动拉取历史训练数据，开始你的科学训练与 AI 复盘！

## 🔒 隐私与数据安全说明

- **本地存储路径**：数据与凭证均保存在用户主目录 `~/.coros-dashboard/` 下（未来将平滑迁移至 `~/.pacecraft/`）：
  ```
  ~/.coros-dashboard/
  ├── profiles/
  │   └── <profile-id>/
  │       ├── coros.db          # 跑友个人独立 SQLite 数据库
  │       ├── tokens.json       # OAuth 授权凭证与 Garmin API Key (chmod 600)
  │       ├── profile.json      # 档案元信息
  │       └── fit/              # 海拔与活动 FIT 缓存文件
  └── ...
  ```
- **权限安全**：授权凭据存储权限严格设为 600（仅当前系统用户可读），且已被 `.gitignore` 深度排除，绝对不会上传到代码仓库。
- **端口隔离**：默认仅监听 `127.0.0.1` 本地回环接口，不向公网暴露端口。
- **数据重置与彻底清理**：
  - **应用内一键抹除**：前往客户端「系统设置」页最底部「本地数据管理与安全重置」，点击即可安全清空本地所有档案、数据库与凭据。
  - **终端手动清理**：如已直接将 App 移入废纸篓，在终端执行 `rm -rf ~/.coros-dashboard` 即可彻底清除全部历史残留。

## 🧠 算法模型与统计依据

PaceCraft 的核心计算与预测**完全基于你真实跑过的分圈（Laps）数据与比赛记录**，脱离厂商闭源黑盒评分。系统拒绝把世界纪录死板硬套在普通跑者身上，用通俗易懂的运动科学逻辑还原你的真实能力：

### 🏃‍♂️ 1. 结构化课型分类：不再把间歇课误当成慢跑
- **跑者痛点**：跑了一堂 1km×6 组高强度间歇，加上热身慢摇总共跑了 10km。很多软件只看单次总里程，粗暴地把它标成“中等距离慢跑”，周报表和 AI 就会误以为你“这周只跑了慢跑，缺乏速度强度”。
- **PaceCraft 解法**：系统看的是**每一圈的真实节奏**。自动检测配速方差，把“快跑组”与“慢摇休息组”自动分离，识别出具体的组次（如 `1km×6组`、平均快跑配速 3:38、组间休息 165 秒）。
- **杜绝误判**：常规匀速 10km 跑各圈配速平稳，坚决不会被误判成间歇；间歇跑也不会去算毫无生理意义的“有氧脱钩率”。

### 📈 2. 真实能力预测：不玩虚标、不盲目乐观
- **拒绝拿间歇拼凑假成绩**：在连续分圈中滑动寻找你真正的 5K、10K 最佳连续成绩。如果中间夹杂着慢跑休息，算法**坚决拒绝跨段拼凑**，避免把间歇跑的走走停停拼成假的“连续 8km 最佳”去虚假拉快全马预测。
- **根据你的真实周跑量，动态调整全马后程掉速**：
  - 经典公式（Riegel）是按世界纪录拟合出来的，直接套在业余跑者身上算全马通常严重偏快（很多人前半程跟着跑，30 公里直接撞墙崩盘）；
  - PaceCraft 结合近 8 周的**平均周跑量**动态校准疲劳指数——周跑量越扎实，预测越有底气；周跑量偏低，模型自动加大后程掉速预期，给出真正能跑出来的目标。
- **纯净的乳酸阈值配速**：只在匀速稳态有氧区间拟合配速与心率，自动剔除间歇跑剧烈波动的心率干扰，算出扎实的乳酸阈值（88.5% HRmax）配速。
- **实测长距离硬核比对**：拿你历史上跑过最硬核的一次长距离（≥40km）作为事实依据，与模型预测对照，给出清晰的 A/B/C 级可信度。

### 🏁 3. 赛事中心实战预测与备赛体检：量身定制赛道战术
- **赛道爬升与海拔折算**：爬坡掉速、下坡省力、高原空气稀薄缺氧，系统根据地形坡度和海拔统一折算为海平面等效用时，不再被难跑的赛道误导。
- **滚动 28 天真实状态窗口**：窗口右端严格锚定在“最近一次训练日”，避开自然周初才跑了两天被当成周跑量暴跌的假象，停跑几天数据指标也绝不会凭空漂移。
- **长距离准备度**：近 4 周有没有跑过 28km 以上的长拉练，直接决定了全马后半程肌肉耐受度与崩盘风险。

### 💓 4. 生理负荷监控与有氧脱钩率
- **急慢性负荷比（ACWR）**：基于心率储备指数计算每堂课的生理刺激（TRIMP），监控短期疲劳（7天）与长期体能（42天）的比例，守住 0.8~1.3 的安全甜点区，跑量猛增或骤减及时预警防伤。
- **有氧脱钩率（Decoupling %）**：只在稳态长距离（≥5km）中计算，对比前后半程的配速与心率比。后半程心率飙升或配速严重衰减（脱钩率 >8%）提示基础有氧不足、脱水或糖原耗尽；前后半程稳定平行（脱钩率 <5%）说明基础有氧极其扎实。

1. **结构化间歇识别与非稳态做功模型**：
   - 参考 **Billat (1996, 2000)** 关于 $v\text{VO}_2\max$ 间歇生理学与 **Skiba et al. (2012, 2015, MSSE/IJSPP)** 临界速度（Critical Speed）与间歇动态恢复理论，算法通过分圈离散度与交替聚类精准分离 Work Reps 与 Recovery 段。
2. **Daniels & Gilbert (1979) VDOT 方程数值求解**：
   - 弃用简陋易撞上限的截断查表，直接采用联立方程二分法高精度求解：
     $$\text{VO}_2 = -4.60 + 0.182258 \cdot v + 0.000104 \cdot v^2 \quad (v \text{ 为速度 m/min})$$
     $$\%\max = 0.8 + 0.1894393 \cdot e^{-0.012778 \cdot t} + 0.2989558 \cdot e^{-0.1932605 \cdot t} \quad (t \text{ 为极限用时 min})$$
     $$\text{VDOT} = \text{VO}_2 / \%\max$$
3. **Riegel (1981) 疲劳幂律与 Vickers & Vertosick (2016, $n=2303$) 周跑量修正**：
   - 传统 Riegel 公式为 $T_2 = T_1 \cdot (D_2 / D_1)^k$。Vickers 等学者对比 2300+ 场全马实测数据证实，周跑量是唯一解释全马疲劳衰减的显著变量，PaceCraft 采用论文回归式校准：
     $$k_{\text{全马}} = 1.4510756 - 0.23797948 \cdot k_{12} - 0.01410023 \cdot (\text{周英里} / 10)$$
4. **Banister (1991) / Morton TRIMP 冲量响应模型**：
   - 心率储备指数加权：$\text{TRIMP} = t \cdot \Delta\text{HR} \cdot 0.64 e^{1.92 \cdot \Delta\text{HR}}$，推导 EWMA 急慢性负荷比（ACWR）。
5. **海拔与地形代偿模型**：
   - 爬坡代价 $1.244\text{ s/km per m/km}$，高原缺氧惩罚 $2.5\text{ s/km per 1000m}$（基于 Saunders 等高原耐力运动生理学研究）。

│   ├── src/
│   │   ├── pages/              # 训练看板、场次复盘与双表比对、赛事中心、身体状态、系统设置

├── .github/workflows/          # GitHub Actions 全自动打包发布工作流
└── scripts/                    # 桌面端侧边二进制构建与部署脚本
